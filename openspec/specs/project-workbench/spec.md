# 项目工作台规格说明

## Purpose

定义认证后的个人项目工作台体验，覆盖登录入口、快速记录、Dashboard 状态总览、项目详情跟踪以及最近更新浏览。
## Requirements
### Requirement: 工作台登录入口页
系统 SHALL 将 `/login` 作为个人项目工作台的产品入口页，同时在同一屏幕保留登录与注册两个操作。

#### Scenario: 已登出访客打开登录页
- **WHEN** 访客访问 `/login`
- **THEN** 页面会明确说明该系统是个人项目工作台，并在同一页面内提供登录与注册两个入口

#### Scenario: 受保护页面重定向到登录页
- **WHEN** 访客带着安全的 `redirect` 查询参数被重定向到 `/login`
- **THEN** 用户登录成功后会回到保留的站内目标路径

### Requirement: 工作台 Dashboard 总览
系统 SHALL 提供一个认证后的 Dashboard 首页，用于汇总 `想法中`、`进行中`、`已暂停` 和 `已完成` 四种状态下的项目数量。

#### Scenario: 认证用户打开 Dashboard
- **WHEN** 认证用户访问 `/`
- **THEN** 页面会展示四个状态总览区块，并显示该用户各状态下的项目数量

#### Scenario: 未认证访客请求 Dashboard
- **WHEN** 没有有效会话的访客请求 `/`
- **THEN** 系统会将该访客重定向到 `/login`

### Requirement: 项目快速记录
系统 SHALL 允许认证用户仅使用项目名称、状态和下一步动作，在 Dashboard 中创建项目。

#### Scenario: 用户提交有效的快速创建表单
- **WHEN** 认证用户提交非空项目名称、一个允许的状态以及非空的下一步动作
- **THEN** 系统会创建该项目，并在用户的 dashboard 中展示出来

#### Scenario: 用户提交不完整的快速创建表单
- **WHEN** 认证用户提交了空白必填字段或不受支持的状态
- **THEN** 系统会以 HTTP `400` 拒绝该请求

### Requirement: 项目列表与筛选
系统 SHALL 在 Dashboard 列表中只展示认证用户自己的项目，并 SHALL 支持按状态筛选。

#### Scenario: 用户查看全部项目
- **WHEN** 认证用户在未应用状态筛选的情况下打开项目列表
- **THEN** dashboard 只展示该用户自己的项目，并按最近更新时间倒序排列

#### Scenario: 用户按状态筛选
- **WHEN** 认证用户应用某个允许的状态筛选
- **THEN** dashboard 只展示该用户在所选状态下的项目

### Requirement: 项目详情工作区
系统 SHALL 提供一个项目详情页，用于展示项目当前状态、当前目标、下一步动作和更新历史。

#### Scenario: 用户打开自己的项目
- **WHEN** 认证用户访问自己拥有的某个项目
- **THEN** 详情页会展示该项目的概览信息以及更新历史

#### Scenario: 用户打开不存在或不属于自己的项目
- **WHEN** 认证用户请求一个不存在或不属于自己的项目标识
- **THEN** 系统会返回 HTTP `404` 或框架等价的 not-found 响应

### Requirement: 项目更新历史
系统 SHALL 允许认证用户为项目追加按时间排序的更新记录，并 SHALL 在 Dashboard 中展示最近更新。

#### Scenario: 用户添加项目更新
- **WHEN** 认证用户为自己的某个项目提交一条非空更新记录
- **THEN** 系统会保存该更新，展示在项目历史中，并同步反映到最近更新区块

#### Scenario: 用户提交空白更新
- **WHEN** 认证用户提交空的项目更新记录
- **THEN** 系统会以 HTTP `400` 拒绝该请求
